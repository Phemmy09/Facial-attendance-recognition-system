Product Requirements Document & Technical Specification

Detailed specifications, data models, workflows, and blueprints for the FaceAttend AI Facial Recognition Attendance System.

1. Executive Summary & Vision

1.1 Product Vision

FaceAttend AI is a state-of-the-art, web-based, zero-installation facial recognition attendance system. It enables schools, universities, and corporate workspaces to track daily attendance for multiple courses, classes, or sessions using a standard laptop or desktop webcam. By executing neural network detection and feature extraction directly inside the browser, it eliminates the need for expensive, specialized biometric hardware while respecting user privacy.

1.2 Core Value Proposition

  • Frictionless Check-in/Check-out: Students simply stand in front of a screen to log attendance. No tags, signatures, cards, or barcodes required.
  • Biometric Integrity: Eliminates proxy attendance ("buddy punching") by matching unique 128-dimensional face descriptor embeddings.
  • Seamless Real-Time Synchronization: Synchronized with a Supabase cloud database, updating administrative logs, registers, and metrics panels instantly.
  • Offline Resilience: Automatically transitions into Local Storage fallback mode if internet access or DB services are offline.

2. User Roles & Access Matrix

Access controls are divided into three distinct operational states to accommodate public scanners, self-service enrollment, and security monitoring.

3. Functional Requirements & Features

3.1 Live Biometric Scanner

Captures video frames and executes facial recognition using convolutional neural networks (CNNs).

  • Detects single faces inside the coordinate bounds.
  • Computes distance matching vectors using a Euclidean distance match score.
  • Implements a 4-second scanner Lockout Cooldown to prevent double scans.
  • Manual scan override button for low-light or lagging streams.

3.2 Dual-State Check-In/Check-Out

Calculates schedule metrics based on configurable lecture settings.

  • Present: Scan recorded within lecture start time + grace period.
  • Late: Scan recorded after grace period.
  • Early Exit: Second scan recorded before lecture end time.
  • Completed: Second scan recorded at or after lecture end time.

3.3 Intelligent Course Registration & Active Enrollment

Ensures students are enrolled in active course sessions. If a recognized student stands in front of the camera but is not registered for the active course session, the system freezes scanning and presents an interactive interface:

Enroll & Check In Action Resume Scan Action

This allows quick enrollment directly from the scanning kiosk, automatically writing the course to the student's profile and checking them in immediately, avoiding manual administrative registry lookup.

4. Non-Functional Requirements

4.1 Performance & Accuracy

  • Biometric Accuracy: Minimum face detection SsdMobilenet threshold of 0.65 and match score limit of 0.55 to prevent false positives.
  • Low Network Burden: Neural network weights (~10MB) are loaded once on startup from a CDN, minimizing network roundtrips.
  • Biometric Anonymization: Raw faces/camera feed are processed purely client-side. The database only stores 128-float mathematical vectors, meaning original photos cannot be reconstructed from database leaks.

6. Database Schema Design (PostgreSQL)

The Supabase relational schema consists of three core tables configured with appropriate constraints:

6.1 Class Settings Table

CREATE TABLE public.class_settings (
    id integer PRIMARY KEY DEFAULT 1,
    start_time time without time zone DEFAULT '09:00:00'::time,
    end_time time without time zone DEFAULT '17:00:00'::time,
    grace_period_mins integer DEFAULT 15,
    courses text[] NOT NULL DEFAULT '{"General"}'::text[],
    updated_at timestamp with time zone DEFAULT timezone('utc'::text, now()),
    CONSTRAINT single_row CHECK (id = 1)
);

6.2 Students Directory Table

CREATE TABLE public.students (
    id text PRIMARY KEY, -- Registration Number (e.g. STU001)
    name text NOT NULL,
    email text NOT NULL,
    courses text[] NOT NULL DEFAULT '{}', -- Array of registered courses
    face_descriptor double precision[] NOT NULL, -- 128-float embedding
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now())
);

6.3 Attendance Registers Table

CREATE TABLE public.attendance (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id text REFERENCES public.students(id) ON DELETE CASCADE,
    date date DEFAULT CURRENT_DATE,
    check_in timestamp with time zone DEFAULT timezone('utc'::text, now()),
    check_out timestamp with time zone,
    status text NOT NULL, -- 'Present', 'Late', 'Early Exit', 'Completed'
    course text NOT NULL DEFAULT 'General',
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()),
    CONSTRAINT unique_student_day_course UNIQUE (student_id, date, course)
);
